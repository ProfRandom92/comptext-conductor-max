# CompText Conductor Max v0.2 Context Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Harden v0.1 into a production-oriented v0.2 context runtime for current Antigravity/Conductor workflows while preserving the six-tool MCP surface and local-first security model.

**Architecture:** Keep the existing deterministic broker and add stronger Conductor project-state detection, bounded I/O, incremental state metadata, retrieval references, result/checkpoint feedback, and host-level evidence. Do not introduce a mandatory vector database or remote indexing service.

**Tech Stack:** Python 3.12+, MCP Python SDK v2, Pydantic v2, Typer, Rich, pytest, Ruff, MyPy, GitHub Actions.

## Global Constraints
- Continue on `feature/context-broker-mcp`; do not modify `main` directly and do not force-push.
- Preserve exactly six primary MCP tools.
- Conductor remains read-only.
- Repository contents remain local by default; no telemetry or remote token-counting.
- Context correctness takes priority over reduction.
- Benchmark claims must come from executed evidence and distinguish `estimated_tokens` from host-reported usage.
