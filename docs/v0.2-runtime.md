# CompText Conductor Max v0.2 Runtime Hardening

Date: 2026-08-08

This document records the v0.2 design changes made after re-checking current official Antigravity, Conductor, and MCP documentation. It complements the original architecture documents; benchmark claims remain governed by `benchmarks/results/latest.json` and host-token claims require a real Antigravity headless run.

## Current upstream baseline

- Antigravity documentation currently identifies Antigravity CLI **v1.1.11** and supports plugin bundles containing `plugin.json`, MCP definitions, hooks, skills, agents, and rules.
- The official plugin manifest schema is `https://antigravity.google/schemas/v1/plugin.json`.
- Custom plugin subagents are Markdown files with YAML frontmatter. v0.2 bundles `context-researcher` as a sandboxed Flash subagent and intentionally omits a static `tools:` list because invalid/unmapped tool declarations can make custom agents unusable.
- Antigravity headless mode supports `--output-format stream-json`. The terminal `result.usage` object reports `input_tokens`, `output_tokens`, `thinking_tokens`, `cache_read_tokens`, and `total_tokens`.
- The official MCP Python SDK v2 line targets the 2026-07-28 protocol revision. CompText continues to use the official `mcp>=2,<3` package and stdio transport.
- Current Conductor projects can contain project context such as `product.md`, `product-guidelines.md`, `tech-stack.md`, `workflow.md`, `tracks.md`, and `code_styleguides/*` in addition to track `spec.md`, `plan.md`, and `metadata.json`. The detector also accepts an optional track `index.md` used by current Google examples.

## Stabilization changes

### Bounded repository I/O

`SecurityPolicy.safe_text()` now performs a bounded binary read rather than `Path.read_bytes()` followed by slicing. A large file therefore cannot be loaded wholesale merely to inspect the first indexed region.

### Current Conductor project state

The detector now returns deterministic project-context and track-context path sets. `spec.md` and `plan.md` remain critical; project context, `metadata.json`, and `index.md` are ranking preferences rather than unconditional context, preventing a new form of Conductor full-dump.

### Closed-loop result and checkpoint state

A small local `.comptext/project-state.json` records the last analyzed result hash / likely files and the latest checkpoint hash per track. Subsequent `ct_context` calls use valid failure files and checkpoint files as ranking signals. State is local, path-validated, and not a new MCP tool.

### Deterministic BM25-style retrieval

Retrieval now combines deterministic BM25-style term scoring with existing path, symbol, Conductor, Git-change, failure, critical, and preferred-context signals. Stable path/line tie-breaking remains in place. No embedding service or vector database is required.

### Incremental warm index

The v2 index cache uses a filesystem-stat key before content hashing. If path, size, nanosecond modification timestamp, index window, and maximum indexed size are unchanged, the broker reuses cached safe slices without reopening the file. A changed stat falls back to bounded content reading and SHA-256-based indexing.

This optimization is a warm-path accelerator, not a cryptographic identity claim. Slice identity continues to use SHA-256 content hashes after content is read.

### Reversible slice references

Search results now carry `ctref:v1:<sha256>` references derived from path, line range, and content hash. `ct_search` accepts exactly one of `query` or `ref`, so a previous slice can be expanded without adding a seventh MCP tool. A ref becomes stale when its underlying content hash changes; it never silently resolves to newer content.

### Antigravity host usage probe

`ct-conductor agy-probe` runs a no-tool headless probe when `agy` is installed and parses the terminal `result.usage` block. If Antigravity is absent, unauthenticated, times out, or returns invalid structured output, the command reports the failure rather than fabricating usage.

This probe proves host usage parsing; it is **not** itself a CompText savings benchmark. A real A/B Conductor workload must compare equivalent tasks before any host-reported reduction is published.

## Context-researcher subagent

`agents/context-researcher/agent.md` is designed to isolate repository exploration from the main agent conversation. It prefers `ct_context`, bounded `ct_search`, summary-first `ct_diff`, and local `ct_result`, then returns a compact evidence handoff. Full reads remain permitted when correctness requires them.

## Quality gate

GitHub Actions now runs:

- `pytest -q`
- `ruff check .`
- `mypy src`
- `python -m build`
- Bandit medium/high gate
- `pip-audit`

A CI workflow existing in a feature PR is not itself proof of success; only the final completed run and its job conclusions count as remote evidence.

## Remaining work

- The connected GitHub API currently reports this repository as **public**, while the original project requirement was private. The available repository connector in this execution environment does not expose a safe visibility-update operation, so this remains an explicit P0 configuration issue rather than being hidden or worked around.
- A real Antigravity A/B benchmark against a representative Conductor project is still required before replacing synthetic `estimated_tokens` evidence with host-reported token savings.
- Lightweight import/symbol graph ranking remains a candidate after BM25 is evaluated on real tasks; it should not be added merely for architectural novelty.
- Cross-process cache/stats concurrency and a SQLite/WAL state backend remain candidates if real multi-agent load demonstrates contention. v0.2 does not claim those problems are solved by the current process-local file stores.
